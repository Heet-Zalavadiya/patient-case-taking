# AI Module — MediKiosk (Member 4)

MediKiosk's conversational clinical history-taking engine, powered by Google Gemini (`gemini-3.5-flash-lite`). It conducts a multi-turn, adaptive patient intake interview using the clinical **SOCRATES** framework, performs Ayurvedic **Dashavidha Pariksha** (when in AYUSH mode), detects acute red-flag emergencies via Gemini function calling with deterministic clinical safety heuristics, and generates physician-ready bilingual summaries (English and Hindi).
  
---

## 1. Setup & Environment

1. Install dependencies:
   ```bash
   pip install google-genai requests python-dotenv
   # Optional, only needed for local microphone recording (quick_test.py 'voice' mode):
   pip install sounddevice numpy
   ```

2. Environment variables in `.env` (at repository root, never committed):
   ```env
   AI_API_KEY=your_gemini_api_key_here
   BACKEND_URL=http://localhost:8000
   ```
   > **Security Note:** `AI_API_KEY` is loaded dynamically via `python-dotenv`. It is never hardcoded, exposed, or printed in logs.
   > **`BACKEND_URL` is required for real integration.** It must point at the running FastAPI backend (`cd backend && uvicorn main:app --reload`, default `http://localhost:8000`). If it's missing, `backend_client.py` falls back to `http://localhost:8000` — make sure that matches where the backend is actually running.

```
│   └── _manual_test.py
└── README.md
```

### Core Components
- **`backend_client` (`ai/services/backend_client.py`)**:
  - The ONLY module that talks to the backend. A thin `requests`-based HTTP client wrapping
    the real FastAPI endpoints in `backend/routers/patients.py` and `backend/routers/clinical.py`.
  - GETs: `/sessions/{id}`, `/patients/{id}`, `/patients/{id}/documents`.
  - POSTs: `/sessions/{id}/turns`, `/sessions/{id}/history`, `/sessions/{id}/ayush`,
    `/sessions/{id}/red-flags`, `/sessions/{id}/summary`; PATCHes `/sessions/{id}` to mark completion.
  - Every call catches connection errors / non-2xx responses and logs a warning instead of
    raising, so the AI module stays testable even when the backend isn't running.
- **`InterviewService` (`ai/services/interview_service.py`)**:
  - Talks to the backend exclusively through `backend_client` over HTTP — **no SQLAlchemy
    models, ODBC drivers, or direct SQL Server connections live in this module.**
  - Fetches actual patient demographics and OCR medical records (via `GET /patients/{id}`
    and `GET /patients/{id}/documents`) to personalize the interview context.
  - Strict SOCRATES questioning (Site, Onset, Character, Radiation, Associated symptoms, Timing, Exacerbating/relieving, Severity) — ONE question per turn, warm tone, non-diagnostic.
  - Sequential inquiry: Chief complaint &rarr; Past medical/surgical &rarr; Medications & allergies &rarr; Family history &rarr; Personal/lifestyle history &rarr; Review of systems (ROS).
  - AYUSH mode: Extended Dashavidha Pariksha assessment.
  - Red-flag detection via `flag_emergency` function tool + deterministic clinical safety net (guaranteeing 100% trigger rate for "chest pain + dyspnoea" and acute stroke/hemorrhage patterns).
  - Structured extraction using `response_schema` / `response_mime_type="application/json"`.
  - Bilingual summary generation in English and Hindi.
  - Auto-syncs every turn, red flag, structured history, AYUSH history, and final summary to
    the backend over HTTP as soon as it's generated.
- **`voice_service` (`ai/services/voice_service.py`)**:
  - Microphone recording via `sounddevice` with amplitude diagnostics (`max_amplitude`).
  - Wraps raw PCM in standard 16-bit 16kHz WAV container before sending to Gemini ASR.
  - `sounddevice`/`numpy` are imported lazily inside the recording functions, so importing
    `ai.services` on a machine/container with no audio hardware still works fine (voice input
    just isn't available there).

> **Session ids must be real.** `InterviewService(session_id=...)` expects the numeric
> `session_id` returned by the backend's `POST /sessions` (created after `POST /patients`).
> A non-numeric or unknown id (e.g. `"test-session-001"`) simply skips loading patient
> context and skips real backend writes — this is intentional, and is how `_manual_test.py`
> runs fully offline.

## 3. Database Schema Mappings (For Member 3 — Backend)

Every dictionary key generated by this module strictly matches the database schema column names:

### A. `structured_history` Table (13 Columns)
Endpoint: `POST /sessions/{id}/history`

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `chief_complaint` | `VARCHAR/TEXT` | Primary symptom or reason for visit |
| `hpi_onset` | `VARCHAR/TEXT` | When and how the symptom began |
| `hpi_character` | `VARCHAR/TEXT` | Nature of pain (sharp, dull, throbbing, etc.) |
| `hpi_radiation` | `VARCHAR/TEXT` | Anatomical spread (e.g. left arm, jaw, back) |
| `hpi_associated_symptoms` | `VARCHAR/TEXT` | Accompanying symptoms (dyspnoea, sweating, nausea) |
| `hpi_timing` | `VARCHAR/TEXT` | Duration, constancy, or frequency |
| `hpi_exacerbating_relieving`| `VARCHAR/TEXT` | Factors worsening or easing symptoms |
| `hpi_severity` | `VARCHAR/TEXT` | Pain score (e.g., 8/10) or qualitative severity |
| `past_medical_surgical` | `VARCHAR/TEXT` | Prior illnesses, hospitalizations, surgeries |
| `drug_allergy_history` | `VARCHAR/TEXT` | Current medications, drug/food allergies |
| `family_history` | `VARCHAR/TEXT` | Family medical history (cardiac, diabetes, etc.) |
| `personal_history` | `VARCHAR/TEXT` | Habits, smoking, alcohol, occupation, lifestyle |
| `review_of_systems` | `VARCHAR/TEXT` | Systemic inquiry (fever, weight loss, etc.) |

*Note: Any parameter not discussed is left as an empty string `""` without hallucination.*

---

### B. `ayush_history` Table (11 Dashavidha Pariksha Columns)
Endpoint: `POST /sessions/{id}/ayush` (populated when `history_mode == "ayush"`)

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `prakriti` | `VARCHAR/TEXT` | Constitutional body type (Vata, Pitta, Kapha) |
| `vikriti` | `VARCHAR/TEXT` | Current dosha morbidity / imbalance |
| `sara` | `VARCHAR/TEXT` | Tissue quality / Dhatu sarata |
| `samhanana` | `VARCHAR/TEXT` | Body compactness and symmetry |
| `pramana` | `VARCHAR/TEXT` | Anthropometry and physical proportions |
| `satmya` | `VARCHAR/TEXT` | Adaptability to diet, climate, and tastes |
| `sattva` | `VARCHAR/TEXT` | Mental temperament and psychological strength |
| `ahara_shakti` | `VARCHAR/TEXT` | Digestive power and metabolic appetite (Agni) |
| `vyayama_shakti` | `VARCHAR/TEXT` | Exercise tolerance, physical endurance, stamina |
| `vaya` | `VARCHAR/TEXT` | Age category and vitality |
| `ahara_vihara_notes` | `VARCHAR/TEXT` | Diet, routine, sleep, and lifestyle observations |

---

### C. `red_flag_alerts` Table (2 Columns)
Endpoint: `POST /sessions/{id}/red-flags`

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `flag_description` | `VARCHAR/TEXT` | Clinical rationale (e.g. `'Chest pain + dyspnoea'`) |
| `severity` | `VARCHAR(10)` | Triage priority (always `'HIGH'`) |

---

### D. `interview_turns` Table (3 Columns)
Endpoint: `POST /sessions/{id}/turns`

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `ai_question` | `VARCHAR/TEXT` | Question asked by the AI assistant |
| `patient_response_text` | `VARCHAR/TEXT` | Patient's response |
| `input_mode` | `VARCHAR(10)` | Input method: `'touch'` or `'voice'` |

---

### E. `clinical_summaries` Table (2 Columns)
Endpoint: `POST /sessions/{id}/summary`

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `summary_text_english` | `TEXT` | Professional physician summary in English |
| `summary_text_local_language`| `TEXT` | Professional physician summary in Hindi (हिंदी) |

Format: Chief Complaint &rarr; HPI &rarr; Past Medical/Surgical &rarr; Drug & Allergy &rarr; Family &rarr; Personal &rarr; ROS (& Dashavidha Pariksha if AYUSH).
